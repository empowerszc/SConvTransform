Principles

原理：为什么这样拆

从 im2col、GEMM 到并行维度，先把“钱花在哪”讲清楚。

原理 01

卷积被拆成三个物理阶段

把“搬运”和“计算”显式分开，每段都有自己的 roofline，才能判断一个优化到底值不值得做。

pack → GEMM → unpack 与各自的瓶颈

pack

im2col 物化，9× 写放大。三种写法都停在 13 GB/s/core ⇒ 已贴带宽顶。

GEMM

kblas 微内核，0.7–2.3 TFLOPS（t32）。效率由 m/n/k 与 tile 是否留在 L2 决定。

unpack

还原 NCHW，占 t1 总时间 5–13%，不是瓶颈。

im2col 图解：滑动窗口变成打包矩阵的列；重叠区域就是 9× 写放大的来源

为什么“写得更聪明”没有用

标量、memcpy、合并写三种独立微基准分别测到 13.17 / 13.33 / 12.39 GB/s—— 三种实现同速，说明瓶颈在单核存储带宽而不是代码写法。继续做 SIMD 化没有空间，这是把打包 归为「搬运」而不是「计算」的依据。

为什么打包只做一次

一个 [Nc, Fh, Fw, Nwin] 打包块会被 Oc/Nf 次 GEMM 复用； filter 打包只在 Nf 变化时重建。复用的价值远大于单次搬运的速度。

原理 02

并行维度是 schedule 的属性

同一个循环嵌套里，只有“写不相交 C 列、body 是完整工作项”的窗口 tile 循环可以并行。

循环嵌套与并行/归约/共享 scratch 的边界
为什么 Nc 不能并行：它是 GEMM 的归约维。同一个输出 tile 被 6 个 Nc 迭代累加，并行后多个线程同时写同一块 C——结果直接错，不是“慢一点”。
原理 03

tile 参数决定一次 GEMM 干多少活

m = Nwin，n = Nf，k = Nc·Fh·Fw。单线程与多核对这三个参数的偏好相反。

Nwin / Nf / Nc 如何映射到 GEMM 的 m / n / k

单线程：大 tile 少调用

Nwin=160、Nf=32、Nc=16–32，把每次 GEMM 的固定开销摊薄。custom_0 的 720 次调用降到更少、更宽。

多核：小 tile 多任务

并行宽度 = 窗口 tile 循环 trip count。但 Nwin 会改变 k3 / tile_c，甚至翻转 IS/WS —— 不能盲目减半。

原理 04

六条设计原则

1

搬运与计算分开

各自贴各自的 roofline；ABI 时间不能算进算法。

2

一次性打包、多轮消费

输入 tile 提到 oc 循环外；filter 打包只在 Nf 变化时重建。

3

粒度跟着形状走

batch=1、Ohw=49 时大 tile 只有 2 个任务；参数必须能自适应。

4

先看端到端口径

kernel-only 会漏掉 pad、alloc、线程创建等固定开销。

5

同二进制 A/B

交错重复、取中位数、用未改动用例给噪声底线。

6

特殊硬件只喂擅长形状

SME 只保留给能铺满 16×16 tile 的 c9/c10，扩面实测全面更慢。
