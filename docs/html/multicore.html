Multicore

多核：把并行留在 IR 里

窗口 tile → scf.parallel → OpenMP；宽度与调度共同决定收益。

多核 01

并行链：只标记一个循环

sconv-parallelize 把“直接嵌套的已标记循环链”折成 scf.parallel； 共享 scratch 的循环不入链。

窗口 tile 循环 → scf.parallel；scratch 按线程取槽

标记

从微内核向上找最近的 step == nwindows 循环；不再用位置索引。

私化

打包在并行区内 → scratch 扩成 [64][...]，按 omp_get_thread_num() 取槽。

共享

打包被 hoist 到并行区外 → buffer 只读，保持共享，不打 parallel_scratch。

正确性红线：Nc 是 GEMM 的归约维。原型并行 Nc 后 8/11 形状错、max_diff 1e6–1e8。现在只并行写不相交 C 列的窗口 tile。

多核 03

M4-c：多核专用 Nwin 与调度保护

“任务更多”不一定更快。Nwin 会改变 k3 / tile_c，甚至翻转 IS/WS。

M4-c 的 Nwin 决策树；c1/c2/9 因 IS→WS 翻转保留 160

采用 candidate

c0/c4/c6/c8/c10：80；c3/c7：40。宽度翻倍，提升 12%–20%（c3/c7 约 6%–8%）。

保留 base

c5（IC=48，打包受限）；c1/c2/9（Nwin=80 翻到 WS，且 c2/9 的窗口组缩到 400，宽度反而 10→5）。

多核 05

五个实现坑

1. alloca_scope 锁死 lowering

convert-scf-to-openmp 无条件包 scope，随后 verifier 报错。新增 sconv-erase-alloca-scope。

2. reinterpret_cast 的 offset

私化后 offset 要以 base 为基准加 tid * slotElements，结果类型改成动态 offset。

3. 不能每迭代 alloc

每次新分配让 t1 从 499 → 820 ms；改成 [64][...] 槽整轮复用。

4. 窗口循环不能按位置选

tiling 顺序会翻转；按 step == nwindows 找。

5. 不是所有打包都在并行区

hoist 的打包只读共享 buffer；无条件私化会让 pass 拒绝构建。

结论

能解释“为什么不继续”与“为什么继续”同样重要：M4-a/b 暂缓，先做 E1/E2/B。
